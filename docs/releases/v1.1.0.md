# Outdoor shower controller v1.1.0

This paired release adds a mobile admin page to the Waveshare ESP32-S3 knob,
configurable shower duration and screen rotation. Its operating scope remains
`manual_timed`; PT100/MAX31865 temperature is informational.

## Changes

- Local `/admin` page with an owner-selected four-digit PIN, sessions, recovery
  code, rate limits and protected settings. Existing Wi-Fi, Pi and Roon settings
  survive the upgrade; firmware boot does not automatically erase NVS.
- Shower duration from one to ten whole minutes. The legacy/default request
  stays ten minutes; a changed duration applies to the next deliberate action.
- Screen and touch rotation at 0/90/180/270 degrees, retained after power cycling.
- Correct IPv4 admin access when ESP-IDF accepts the connection on a dual-stack
  IPv6 socket. Foreign Host/Origin checks remain enforced.
- Internal Pi protocol 2 explicitly distinguishes `begin` from `renew`. An
  expired/restarted daemon lease cannot be rearmed by an old renewal. Manual
  recovery requires DRAIN/fault clearance and a distinct fresh START.
- The dial discards an unsent START aged ten seconds or more. An already
  accepted Pi timer continues during ordinary dial Wi-Fi loss.

## Install and rollback

Upgrade the Pi Hub, paired daemon, both installed clients and paired Node-RED
flow together through the reviewed stopped/drained procedure. Preserve unrelated
flows, protected credentials and the pre-upgrade configuration. Require protocol
2 startup DRAIN and capability before using a shorter interval. The wheel alone
does not install the daemon or flow; use the complete source/deployment assets.
Do not enable `automatic` mode as part of this upgrade.

Use the attached exact four-region dial bundle; preserve NVS and do not perform
a whole-chip erase. Publication itself does not reinstall either device. The
currently tested installation already contains the released control behavior.
Keep valve 24 V disconnected during any separately authorized deployment.

The original v1.0.0 releases and assets remain unchanged. Restore the whole
compatible Pi stack while stopped/drained if rolling back; no hot protocol
downgrade during an active interval. A dial with a shorter saved duration must
refuse START when the old Pi lacks the capability. Restore the tested v1.0.0
dial bundle with protected NVS/config as needed; old firmware may lack the web
PIN gate, so retain trusted-LAN access.

The inherited multi-board publisher and master-changelog job exclude this exact
system tag, preserving the tested bundle and avoiding unrelated board releases.
